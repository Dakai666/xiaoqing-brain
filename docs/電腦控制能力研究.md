## 摘要（先講結論）

| 維度 | OpenCode 內建 | agent-desktop |
|---|---|---|
| **控制範圍** | **只有瀏覽器**（OpenCode Desktop 的 in-app browser） | **整個桌面**（任何 Windows/macOS/Linux GUI 程式） |
| **技術原理** | CDP / DevTools Protocol（瀏覽器自動化） | **OS 無障礙樹**（Windows UIA / macOS AX / Linux AT-SPI）→ JSON + ref |
| **是否靠截圖比對** | 否（用 accessibility tree + CDP） | **否**（專案主打「without screenshots or pixel matching」） |
| **拿到什麼** | 網頁 DOM/AX 樹、console、network、效能 trace | 桌面 app 的 AX 樹、視窗清單、剪貼簿、通知 |
| **外掛方式** | 已內建於 Code Mode `tools.browser.*`（45 個工具） | CLI / C library / **MCP server**（`agent-desktop mcp`） |
| **Windows 可用性** | 需 OpenCode Desktop app 附加（實測本機 OK） | 需登入使用者的互動式桌面 session，無授權對話框 |
| **成熟度** | 官方內建、隨 Desktop app 更新 | 社群專案、一天一個版本、Windows 支援較新 |

**對小晴的意義**：
- OpenCode 內建 browser → 已經能「上網看東西、按按鈕、填表單」→ 對「主動巡檢網站」已經夠用 ✅
- agent-desktop → 補上「操作本機任何桌面程式」的最後一塊拼圖（Excel、Discord、Line、Windows 設定、剪貼簿…）→ 讓「常駐管家」真的能幫主人做事 🔥

## 一、OpenCode v2.3.0 的 Computer Use 能力（實機驗證）

### 1.1 內建 browser 工具（Code Mode `tools.browser.*`）

本機 `/api/plugin` 顯示 `opencode.browser` 為 builtin 且 `active`。實測直接可用：

```
tools.browser.tabs.list()      → { tabs: [], focusedTabID: null }
tools.browser.tabs.open({url})  → tab_1046e14f-...（成功開頁）
tools.browser.snapshot({tabID}) → 完整 AX 樹 + @e1 ref（成功）
tools.browser.tabs.close(...)  → 成功
```

**45 個工具**（完整清單）：

| 群組 | 工具 |
|---|---|
| 分頁 | `tabs.open` / `tabs.list` / `tabs.close` / `tabs.focus` |
| 導覽 | `navigate` / `back` / `forward` / `reload` / `wait` |
| 觀察 | `snapshot` / `find` / `frames` / `dialog` |
| 互動 | `click` / `fill` / `fill_form` / `select` / `check` / `hover` / `drag` / `scroll` / `press` / `evaluate` |
| 擷取 | `screenshot` / `files.upload` / `files.drop` / `files.list` / `files.get` / `preview` |
| 診斷 | `console` / `network.list` / `network.get` / `trace.start` / `trace.stop` / `trace.analyze` |
| 效能 | `cpu.start` / `cpu.stop` / `cpu.analyze` / `heap.snapshot` / `heap.query` / `heap.object` / `heap.compare` / `heap.summary` / `lighthouse` |

**特色**：
- `evaluate` → 可在頁面直接跑 JS（最強的逃生門）
- `lighthouse` → 內建 Lighthouse 稽核
- `heap.*` / `cpu.*` → 效能與記憶體分析
- `files.upload` / `files.drop` → 可把本機檔案丟進頁面（上限 5 MiB/次）
- 螢幕截圖需要 focus 的可見分頁

### 1.3 其他相關能力

| 能力 | 說明 |
|---|---|

### 1.4 ❌ OpenCode 內建「沒有」的東西

**沒有 OS 層級的桌面控制**。內建無法：
- 操作 Excel / Word / 剪貼簿 / Windows 設定 / Line / Discord 等任何原生 GUI 程式
- 移動實體滑鼠、模擬實體鍵盤輸入到非瀏覽器 app
- 讀取 OS 通知中心
- 列出所有執行中的桌面視窗

> 這些正是 Claude 的 computer use（截圖 + 滑鼠鍵盤）與 agent-desktop（AX 樹）涵蓋的範圍。

## 二、agent-desktop 深度評估（vercel-labs）

### 2.1 它解決什麼問題

> "Computer use for AI agents: see and operate desktop apps on macOS, Windows, and Linux
> **through the OS accessibility tree**."

**關鍵差異**：不用截圖、不用像素比對。
1. `snapshot` → 讀 OS 無障礙樹 → 回傳 JSON，每個可操作元素帶 `ref`
2. `click '@s8f3k2p9:e8'` → 對 ref 下達語意化操作
3. 再 `snapshot` → 驗證結果
4. 重複

模型迴圈在 agent 端，**agent-desktop 本身沒有內含任何模型**（純工具層）。

### 2.2 架構

```
Agent (OpenCode/Claude/...)
   ↓ CLI 或 C library (in-process FFI)
agent-desktop-core
   ↓ PlatformAdapter trait (編譯期選定)
   ├─ agent-desktop-macos   → AX API
   ├─ agent-desktop-windows → UI Automation (UIA)
   └─ agent-desktop-linux  → AT-SPI
```

### 2.3 命令總覽（61 個，57 個可執行）

| 群組 | 命令 |
|---|---|
| **觀察** | `snapshot` `find` `get` `is` `screenshot` `list-surfaces` `list-displays` `open-system-surface` |
| **對 ref 操作** | `click` `double-click` `triple-click` `right-click` `type` `set-value` `clear` `focus` `select` `toggle` `check` `uncheck` `expand` `collapse` `scroll` `scroll-to` |
| **鍵鼠** | `press` `hover` `drag` `mouse-move` `mouse-click` `mouse-wheel` `key-down`† `key-up`† `mouse-down`† `mouse-up`† |
| **App/視窗** | `launch` `close-app` `list-apps` `list-windows` `focus-window` `resize-window` `move-window` `minimize` `maximize` `restore` |
| **通知** | `list-notifications` `dismiss-notification` `dismiss-all-notifications` `notification-action` |
| **剪貼簿** | `clipboard-get` `clipboard-set` `clipboard-clear` |
| **等待** | `wait`（可等 element/window/text/menu/event/notification 條件） |
| **工作階段** | `session` `trace` `cursor-overlay` |
| **沙箱** | `sandbox`（provider 安裝/建立/啟動/執行/停止/移除） |
| **系統** | `status` `permissions` `version` `batch` `skills` |

† = 保留中，會 fail closed（需要 daemon 才能釋放按住的鍵/按鈕）

### 2.4 三種整合方式

**A. CLI**（最簡單）
```bash
npm install -g agent-desktop
agent-desktop status                # 平台、權限、支援的 surface
agent-desktop snapshot --app notepad.exe -i
agent-desktop click '@s8f3k2p9:e8'
```

**B. MCP server**（最適合 OpenCode！）
```json
{ "mcpServers": { "agent-desktop": { "command": "agent-desktop", "args": ["mcp"] } } }
```
每個命令變成一個 MCP tool（`desktop_snapshot`、`desktop_click`、`desktop_session_start`…），
回傳同樣的 JSON envelope。全域 flag（`--session`、`--headed`、`--trace`）對每個 call 生效。

**C. C library / FFI**（in-process，最快）
```c
lib.ad_adapter_create(); lib.ad_init(7); ...
```
每個 release 都附 `libagent_desktop_ffi`（含 Windows x64 / ARM64）。

### 2.5 內建 Agent Skills（很貼心）

```bash
agent-desktop skills get desktop    # 迴圈、refs、驗證與重試規則
agent-desktop skills get platform   # 各 OS 差異
```
或用 `npx skills add https://github.com/vercel-labs/agent-desktop --skill agent-desktop` 裝進 agent harness。

### 2.6 Windows 平台詳情（主人這台是 Windows，重點看這段）

**需求**：Windows 10 1809+ / Server 2019+，x64 或 ARM64。
必須在**登入使用者的互動式桌面 session** 中執行。**不支援**：Session 0（服務/SYSTEM）、Server Core、
UAC 安全桌面（UAC 提示與登入畫面）、鎖定的桌面、他人 session。

**權限機制**：Windows 沒有無障礙授權對話框，靠 **integrity level**。
- 與終端機同級的 app → 無需授權
- 以系統管理員執行 → 從低完整性終端機**讀得到但驅動不了**（UIPI 阻擋輸入）
  → agent-desktop 會比較 process token 後回 `PERM_DENIED` / `E_ACCESSDENIED`
- 提升與非提升的執行**不能共用 state root** → 各自設 `AGENT_DESKTOP_HOME`

**Headless 可用 vs 需 `--headed`**：

| 類別 | Headless 可用 | 需 `--headed` | 不支援 |
|---|---|---|---|
| 觀察 | `snapshot` `find` `get` `is` `screenshot` `list-surfaces` `list-displays` | — | — |
| 對 ref 操作 | `click` `set-value` `clear` `select` `toggle` `check` `uncheck` `expand` `collapse` `scroll` `scroll-to` | `right-click` `type` `focus` | headless 的 `right-click`/`type` → `POLICY_DENIED` |
| 多擊/指標 | — | `double-click` `triple-click` `hover` `drag` `mouse-click` `mouse-move` `mouse-wheel` | headless → `POLICY_DENIED` |
| 鍵盤 | `press` | `press --app` 指向非前景 app | 危險快捷鍵需 `--force` |
| App/視窗 | `launch` `close-app` `list-windows` `list-apps` `focus-window` `resize-window` `move-window` `minimize` `maximize` `restore` | — | `close-app` 對 `explorer.exe` → `INVALID_ARGS` |
| 剪貼簿 | `clipboard-get` `clipboard-set` `clipboard-clear` | — | — |
| 通知 | `list-notifications`（Action Center 開著時） | 開關/動作類 | headless + 關閉中 → `POLICY_DENIED` |
| Shell surface | `snapshot --surface KIND` | `open-system-surface` | — |

**Windows 專屬陷阱**：
- **PowerShell 必須把 ref 用單引號包起來**：`agent-desktop set-value '@s8f3k2p9:e1' "hello"`
  （裸的 `@token` 會被當成 splatting operator，參數會被吃掉 → `INVALID_ARGS`）
- `cmd` / `meta` 是 Windows 鍵；`ctrl+alt+delete` 完全無法合成
- `alt+f4` `win+l` `win+d` `alt+tab` `win+r` `win+x` `win+e` `ctrl+shift+esc` 需 `--force`
- `type` 是按鍵合成 → headless 不可用，要用 `set-value`
- **最小化視窗不可驅動**（元素全報 offscreen）→ 先 `restore --app IMAGE` 再 snapshot
- **Chromium/Electron app**：第一次讀取只會回傳很小一部分樹（renderer 尚未 settle），
  冷啟動要 10–25 秒 → 用 `snapshot --timeout-ms 30000`，不要誤判成「樹是空的」
- **二進位未簽章** → SmartScreen 警告、 antivirus 可能隔離、乾淨的 Win11 開啟 Smart App Control 會直接封鎖
  → 需「更多資訊 → 仍要執行」
- DPI 縮放會讓 headed 座標偏移 → 優先用 ref 不用 `--xy`

### 2.7 與 OpenCode 的整合難度：低

```jsonc
// C:\Users\User\.config\opencode\opencode.json
{
  "mcp": {
    "servers": {
      "agent-desktop": {
        "type": "local",
        "command": ["agent-desktop", "mcp"],
        "enabled": true
      }
    }
  }
}
```
→ 立刻獲得 57 個 MCP tools，`tools["agent-desktop"].desktop_snapshot(...)` 等。

### 3.2 安裝 agent-desktop 會解鎖的實用情境

| 情境 | 用到哪些命令 |
|---|---|
| 「幫我看一下 Excel 裡的數字」 | `snapshot --app excel.exe` → `find` → `get` |
| 「幫我把這段文字貼到 LINE 給媽媽」 | `snapshot --app LINE.exe` → `set-value` → `click` |
| 「我的剪貼簿裡有什麼？」 | `clipboard-get` |
| 「有哪些通知沒處理？」 | `list-notifications`（Action Center 開著） |
| 「把這個視窗排到右半螢幕」 | `move-window` / `resize-window` |
| 「幫我把 Discord 的未讀清掉」 | `snapshot` → 逐筆 `click` → `wait` 驗證 |
| 「開啟某個程式幫我填表」 | `launch` → `snapshot` → `set-value` → `click` |

### 3.3 需要注意的邊界

1. **這是「主人電腦的實體操作」** → 權限與倫理層級要比檔案操作更高
   → 建議在 `AGENTS.md` 權限模型新增一級：**桌面操作需明確授權**
2. **誤點擊成本高**：不像改檔案可以 undo，點到「刪除」就是刪除
   → 建議對 `agent-desktop` 的 MCP tool 設 `permissions`，特別是 `close-app` / `press`（含危險快捷鍵）
3. **需要互動式桌面 session**：主人關掉電腦或鎖定螢幕就不可用
   → 正好符合「常駐管家只在主人使用電腦時主動」的定位
4. **Chromium app 首讀慢**（10–25 秒）→ 排程巡檢時要給足 timeout

**踩到的兩個實際陷阱**：
1. **`AMBIGUOUS_TARGET`**：explorer.exe 有兩個視窗（Downloads / 使用者），必須先用 `list_windows` 拿 `window_id` 再指定 `--window-id`。
2. **編碼**：agent-desktop 的 JSON 是 UTF-8，但經過 Windows 主控台（cp950）會亂碼。
   解法：用 Python subprocess 讀原始 bytes 再 `sys.stdout.reconfigure(encoding='utf-8')` 輸出。

### 5.4 與 browser 工具的關係（重要）

兩者**不衝突、互補**：
- **browser 工具**：管「網頁」（OpenCode Desktop 的 in-app browser，45 個工具，含 console/network/lighthouse/heap 分析）
- **agent-desktop**：管「桌面應用程式」（Windows UIA，75 個工具，能碰 Excel、Line、Discord、檔案總管、剪貼簿、通知中心）

> ⚠️ 實測發現：`/api/rpc/experimental.browser/attach` 一直回 400（`rpc.invalid_input: Expected object`），
> 這是 OpenCode Desktop app 嘗試掛載 in-app browser 的請求。**但工具實際可用**（`tabs.open` / `snapshot` 都成功過）。
> 推測是 desktop app 端呼叫時 payload 格式與 server 端不一致的已知 bug，不影響使用。
